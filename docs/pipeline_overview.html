Pipeline services — what each one does

ServicePurposeReads fromWrites / sends toSchedule
moveFiles.py Moves freshly downloaded camera files from the local cache disk into the cloud mount, organized into date folders parsed from the filename (e.g. R20250527_1851.MP4). /Volumes/cacheDisk/…/<date>/raw/; WebSocket (port 8081) download events signCollect mount …/<date>/raw/ via rsync Every 15 min
batch_queue.py Drives DaVinci Resolve: builds a timeline per raw video, applies the Fusion composition (config/Settings.setting) for green-screen removal and background replacement, renders in batches of ≤50. Writes .skip markers for failed files. mount …/raw/ → local import/ local export/ → mount …/post_noncropped/ Continuous
crop.py AI cropping: extracts frames, runs MediaPipe pose detection to find the signer (head-to-waist bounds, nose-centered), corrects camera tilt, crops to 1440×1252, re-encodes with ffmpeg, generates a thumbnail, and uploads the result. mount …/post_noncropped/; temp frames in temp/frames_* (auto-cleanup >1 h / >10 GB) mount …/post_cropped/ + thumbnails/; upload → upload_post.php Continuous
convertFiles.py Web-friendly conversion of the raw recordings: ffmpeg libx264/aac/yuv420p baseline profile + a thumbnail taken at the 50% mark, then upload. mount …/raw/ (skips dates that already have converted/) mount …/converted/ + thumbnails/; upload → upload2.php Hourly
qr_scanner_service.py Scans thumbnails for QR codes (used to link recordings to session/sign IDs) with a 4-worker pool (QReader + pyzbar). Remembers what it already scanned. mount …/thumbnails/*.jpg (last 7 days); state in qr/scanned_files.json upload → qr/qrResultReceiver.php Every 15 min
listFiles.py Quality/completeness reporting: counts files per camera (L/M/R/A/B) for the last 10 dates, verifies all cameras recorded equally, computes glosId coverage against the expected list from CR.php. mount …/raw/ + sidecar JSONs; cache in logs/glosids_cache/ POST inventory JSON → listFiles.php Hourly
How the stages chain: each stage is decoupled — services don't call each other. They watch directories on the shared rclone mount and act when new files appear: raw/ → (Resolve) → post_noncropped/ → (MediaPipe) → post_cropped/. That makes the pipeline self-healing: if a stage was down, it simply catches up on the backlog when restarted.
